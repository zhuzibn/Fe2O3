03 / Carry the endpoint, but sample only through gpusteps

The endpoint is copied into tmp2*n0 and becomes the next chunk’s initial spin. The PR explicitly samples 1:savetstep:gpusteps, excluding slot gpusteps+1. This preserves the frame count and avoids saving a chunk endpoint twice. After the last chunk, the endpoint buffers are cleared.

DMI-history sampling lines are included because they share the same frame-selection range. No DMI formula or field-recording correction is reviewed here.

    eval(shifts);eval(exchange);

        sy=eval(sprintf('mmytmpJ%d',shell));
        sz=eval(sprintf('mmztmpJ%d',shell));
        assert(isequal(sx,sy) && isequal(sx,sz));

    end
    eval(dmiCode);
    if ispr

        s=dmi_sumx;
    else

    end
    W(:,j)=s(occupied);
end
end

05What remains open

  1. Decide whether the final-time state must be saved. The PR chooses half-open chunk sampling: include the chunk start and exclude its end. That is coherent for intermediate chunks, but the final endpoint is never recovered. At default settings, a restart from mmx(:,:,:,end) resumes at 149.5 ps. Saving the 150 ps endpoint requires a matching timestamp and, if included, a DMI field evaluated from that endpoint. Alternatively, explicitly accept and document the current policy. This output limitation existed before the PR; it is not a newly introduced regression.
  2. Synchronize the issue record and current-behavior documentation. The PR changes only MATLAB files. Its README and methodology still state that each chunk performs 9,999 updates and that TIME-01 is retained. Historical import records can remain, but they need a clearly separated resolution entry for this revision.
  3. Keep the validation boundary explicit. The small checks cover integral step ratios, strides 1/2/8, the default RK4 path, and disabled dipole coupling. They do not establish timestep convergence, alternative solvers, non-integral gpusave/tstep behavior, or full-size memory/runtime performance. The extra endpoint slot is dynamically grown; production memory cost was not benchmarked.

Related concern from the 21 October discussion: updating effective fields inside RK4 substages is a separate numerical question. This PR’s timing changes do not address it. The fields remain fixed within each nominal step.
